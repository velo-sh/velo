# RFC-0009: Phase 6.0 - Static Import Graph

> **Status**: ✅ ACTIVE (Approved for Development)  
> **Author**: Architect (ID-LOCK-001)  
> **Created**: 2026-01-03  
> **Revised**: 2026-01-03 (Ratified by Joint Expert Committee)  
> **Target Version**: v0.6.0

---

## 1. Summary

This RFC proposes a **Static Import Graph** system that pre-computes and caches all module dependencies at build time, eliminating the need for `stat()` filesystem lookups during cold start. This builds upon the Phase 5.0 Fast Loader foundation to further reduce I/O overhead.

## 2. Motivation

### 2.1 The Problem
Even with the Fast Loader, Python's import system still incurs significant overhead from:
1. **`stat()` calls**: Every `import foo` triggers multiple filesystem lookups to find `foo.py`, `foo/__init__.py`, etc.
2. **Path resolution**: The import machinery walks `sys.path` entries, calling `os.path.exists()` repeatedly.
3. **Race conditions**: In serverless/containerized environments, cold filesystem caches amplify latency.

### 2.2 The Opportunity
Since Velo bundles already contain a complete module index, we can **pre-compute the entire import graph** at bundle creation time. During execution, the loader can skip all filesystem operations and resolve imports directly from the graph.

## 3. Design Overview

### 3.1 Core Concept: Import Graph

```
┌─────────────────────────────────────────────────────┐
│                   Static Import Graph               │
├─────────────────────────────────────────────────────┤
│  main.py ──► [app.models, app.services, fastapi]   │
│  app.models ──► [app.db, pydantic]                 │
│  app.services ──► [app.models, httpx]              │
│  ...                                                │
└─────────────────────────────────────────────────────┘
```

The graph is a directed acyclic structure mapping each module to its direct dependencies.

### 3.2 Data Structure (P1-011 Flattened + P2-018 PHF)

```rust
/// Static import graph stored in bundle.
/// Optimized for truly constant O(1) lookup and cache packing.
#[derive(Serialize, Deserialize, Archive, CheckBytes)]
#[archive(check_bytes)]
pub struct ImportGraph {
    pub version: u32,
    pub target_arch_id: u8,   // S-01: Strict Arch Identification
    pub endianness: u8,        // S-01: 0=LE, 1=BE
    
    /// Flattened dependency pool (contiguous memory)
    pub dependency_pool: Vec<String>,
    
    /// Perfect Hash Function (PHF) lookup table (P2-018)
    pub phf_table: StaticPerfectHash<u32>,
    
    /// Packed module records (P2-020)
    pub module_records: Vec<ModuleRecord>,
    
    pub load_order: Vec<String>,
    pub source_hash: [u8; 32],
    
    // === Audit Additions ===
    pub mutable_path_packages: HashSet<String>,
    pub search_locations: HashMap<String, Vec<String>>,
    pub namespace_packages: HashSet<String>,
    
    /// Explicit __path__ storage for packages (P-02)
    /// module_name_index -> initial_path_string
    pub package_paths: HashMap<u32, String>,
}

#[derive(Serialize, Deserialize, Archive, CheckBytes)]
pub struct ModuleRecord {
    /// Bit-packed field (P2-020):
    /// [0..31]  pool_start offset
    /// [31..32] is_package flag
    pub packed_start_info: u32,
    
    /// Number of dependencies
    pub pool_len: u32,
}
```

### 3.3 Integration with Bundle Format

The import graph will be stored as a new section in the `.veloc` bundle.

> [!IMPORTANT]
> **H-9: Page Alignment (S-02)**: The Import Graph Section MUST start at a **4,096-byte (4KB) aligned** offset within the bundle. 
> - **Padding**: All padding bytes MUST be set to `0x00` to maximize compression efficiency.
> - **Performance**: Enables high-efficiency OS readahead and zero-copy page table mapping.

```
┌──────────────────────────────────────────┐
│ Header (128 bytes)                       │
├──────────────────────────────────────────┤
│ Data Section (module bytecodes)          │
├──────────────────────────────────────────┤
│ Index Section (module entries)           │
├──────────────────────────────────────────┤
│ == Padding (0-4095 bytes, 0x00) ==       │  <-- Page Alignment
├──────────────────────────────────────────┤
│ [NEW] Import Graph Section (rkyv)        │  <-- Phase 6.0
└──────────────────────────────────────────┘
```

## 4. Technical Specification

### 4.1 Graph Construction (Build Time)

1. **AST Analysis**: Parse each `.py` file and extract all `import` and `from ... import` statements.
2. **Dependency Resolution**: Resolve relative imports to absolute module names.
3. **Graph Building**: Construct the directed graph of dependencies.
4. **Circular Import Detection**: Use Tarjan's SCC algorithm.
5. **String Interning (P2-019)**: Compress module name prefixes (e.g., intern frequent package stems) to reduce dictionary size for 1000+ module projects.
6. **Perfect Hash Generation (P2-018)**: Generate a collision-free PHF table for the exact set of modules in the bundle.
7. **Topological Sort**: Compute optimal load order.
8. **Serialization**: Store using `rkyv` with `bytecheck` metadata.

### 4.2 Graph Usage (Runtime)

1. **Preload Phase**: When bundle opens, map the graph section into memory.
2. **Validation (P0-006, SEC-01)**: 
   - Runtime MUST check `target_arch_id` and `endianness`. If mismatch: **DISABLE GRAPH (Fallback)**.
   - Use `rkyv::check_archived_root_with_context` with:
     - **Depth Limit**: Max 100 levels.
     - **Validator Limit**: Max 10MB memory.
     - **DoS Protection**: Do not trust offsets from disk without validation.
3. **Import Hook (P-01)**: When `VeloFinder.find_spec()` is called:
   - **Step 1: sys.modules Check**: If module in `sys.modules`, return its spec immediately.
   - **Step 2: Static Graph Lookup**: If not in `sys.modules`, query the graph.
   - If module is in graph:
     - Check for SCC/Cycle (P2-021).
     - If in a cycle: Return spec normally but disable graph-based preloading for this subtree.
     - **Path Sanitization (SEC-02)**: Verify any retrieved `search_locations` do NOT contain `..` and resolve within Bundle Root.
     - Else: Return spec directly (no `stat()`).
   - If module is NOT in graph: Fall back to standard import.
3. **Lazy Loading**: Optionally pre-load modules in topological order for predictable startup.
4. **mmap Lifecycle (P2-012)**: The graph mmap SHOULD remain mapped for process lifetime to benefit from page cache warmth across Zygote workers.

### 4.3 Import Protocol Compliance (P0-001, P0-002)

> [!IMPORTANT]
> The following rules are MANDATORY for CPython behavioral parity.

#### 4.3.1 `builtins.__import__` Preservation (P0-002)
The static graph MUST NOT bypass `builtins.__import__`. The graph only accelerates the **module finding** phase:
- ✅ Graph accelerates: `MetaPathFinder.find_spec()`
- ❌ Graph does NOT replace: `builtins.__import__()` or `importlib.import_module()`

All imports MUST still flow through the standard import machinery to preserve:
- Testing frameworks (pytest, unittest.mock)
- Debugging/profiling tools
- Import hooks installed by frameworks

#### 4.3.2 `__path__` Mutation Handling (P0-001)
For packages in `mutable_path_packages`:
- The graph is used for the package itself
- All submodule lookups MUST fall back to standard import
- This ensures packages that dynamically extend `__path__` (Django, Flask plugins) work correctly

#### 4.3.3 PEP 690 Lazy Imports (P1-006)
Before using graph-based preloading:
```python
if sys.flags.lazy_imports or os.environ.get('PYTHONDEBUG') == 'L':
    # Disable preloading, but still use graph for find_spec
    preload_enabled = False
```

#### 4.3.4 `submodule_search_locations` (P1-007)
When constructing `ModuleSpec` for a package:
```python
spec = ModuleSpec(
    name=fullname,
    loader=VeloLoader(...),
    is_package=True,
    origin=...,
)
spec.submodule_search_locations = graph.search_locations.get(fullname, [])
```

### 4.4 Cache Invalidation

The `source_hash` field ensures correctness:
- Computed as BLAKE3 hash of all source files in the bundle
- If source files change, the graph is automatically invalidated
- Rebuild triggered on next `velo build` or `velo run --fast`

## 5. Performance Targets

### 5.1 High-Level Targets

| Metric | Current (v0.5.x) | Target (v0.6.0) | Method |
|--------|------------------|-----------------|--------|
| `stat()` calls **per import** | ~50-100 | **0** for bundled modules | Graph lookup |
| Cold start (Simple Script) | 17.7ms | **< 10ms** | No fs overhead |
| Cold start (FastAPI) | ~500ms | **< 400ms** | Reduced import I/O |
| Memory overhead | N/A | **< 200KB** for 500 modules | rkyv efficiency |
| Graph deserialize | N/A | **< 500μs** | rkyv zero-copy |

> [!NOTE]
> **Corrected claim (P0-004)**: "0 stat()" applies to **per-import** lookups. Fixed overhead remains for bundle open and cache validation.

### 5.2 Latency Budget Breakdown (P1-008)

| Phase | Target | Notes |
|-------|--------|-------|
| Bundle open + verify | < 2ms | Includes stat(bundle.veloc) + BLAKE3 |
| Graph deserialize | < 0.5ms | rkyv zero-copy access |
| Import resolution | < 0.1ms/module | HashMap lookup |
| First module exec | < 1ms | marshal.loads |
| **Total (simple script)** | **< 10ms** | Sum of above |

## 7. Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| Dynamic imports miss the graph | Fallback to standard import; document limitation |
| Graph becomes stale | `source_hash` invalidation + clear error messages |
| Circular imports | Detect with Tarjan's SCC; emit WARNING, not error |
| Large graphs slow down startup | rkyv zero-copy; lazy loading option |

## 8. Security Invariants

> [!IMPORTANT]
> The following invariants are MANDATORY for Phase 6.0 implementation.

### H-8: Graph Integrity (P1-013 Keyed BLAKE3)
The Import Graph section MUST be cryptographically bound to the bundle.
- **Keyed Mode**: The graph hash MUST be computed using BLAKE3 in **Keyed Mode**.
- **Domain Separation**: Use context-specific derivation for the H-8 key: `Velo-v1-StaticGraph-v0.6.0`.
- **Inclusion**: The resulting graph hash MUST be stored in the bundle index and covered by the global BLAKE3 hash (H-1).
- **Enforcement**: Any tampering or "mix-and-match" of graphs between bundles will cause `LoaderError::BundleCorrupted`.

### H-10: Adversarial Defense (SEC-01/02)
- **Depth Protection**: rkyv verification MUST enforce a nesting limit of 100 levels to prevent stack exhaustion from "graph bombs".
- **Path Sanitization**: The loader MUST validate all `search_locations` at runtime. Any path containing `..` or resolving outside the Bundle Root MUST trigger an immediate `SecurityError`.
- **Arch Pinning**: The graph MUST be pinned to the `target_arch_id` stored in the header. Mixed-architecture execution is prohibited in v0.6.0.

### H-4: Fingerprint Binding (P1-014 Machine Key Protocol)
To prevent pre-computation attacks across different machines:
- **Derive Key Mode**: The `machine_key` used for cache fingerprinting MUST be derived using BLAKE3 in **Derive Key Mode**.
- **Source**: Use the local system's unique hardware identifier (e.g., `/etc/machine-id` or `IOPlatformUUID`).
- **Context/Salt**: Use a constant 32-byte salt: `Velo-Unique-Machine-Key-v1-2026`.
- **Domain**: `Velo-v1-MachineFingerprint`.

## 9. Known Limitations

> [!WARNING]
> The following import patterns are NOT captured by static analysis.

### 9.1 Conditional Imports (P1-001)
```python
if USE_ASYNC:
    import asyncio  # NOT captured statically
else:
    import threading
```
**Behavior**: These modules will trigger a fallback to standard import at runtime. No error, but no `stat()` elimination benefit.

### 9.2 Dynamic Imports (P1-002)
```python
mod = importlib.import_module(f"plugins.{plugin_name}")  # NOT captured
```
**Behavior**: Dynamic imports always fall back to standard import. Plugin systems will work correctly but will not benefit from the static graph.

### 9.3 Namespace Packages (P1-005)
Namespace packages (PEP 420) that span **multiple source roots** are not fully supported:
```
/path1/mypkg/subA/   # Source root 1
/path2/mypkg/subB/   # Source root 2 (different sys.path entry)
```
**Behavior**: Only modules from the bundled source root are captured. Contributions from other `sys.path` entries trigger fallback.

### 9.4 Mitigation: Graph Metrics (OPS-01)
The loader MUST track and report optimization metrics when `VELO_REPORT_METRICS=1` is set.
- **Output**: JSON blob to `stderr` or specified path.
- **Fields**: `graph_hits`, `graph_misses`, `fallback_reasons` (e.g., `dynamic_import`, `namespace_split`).
