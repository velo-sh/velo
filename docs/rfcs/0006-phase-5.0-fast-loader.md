| Scenario | Traditional | mmap Bundle |
|----------|-------------|-------------|

### Key Insights

1. **Cold start**: Bundle is **40% faster** (key for serverless!)
2. **Warm cache**: Minimal difference (~10%)
3. **Single read + slice**: Fastest approach (**5x** in cold start)
4. **Serverless focus**: Cold start optimization is primary value

### Recommendation

- ✅ **Proceed** with bundle implementation for serverless
- 📦 Use **single read + slice** (not mmap) for simplicity
- 🎯 Target: Serverless cold start acceleration

## 1. Executive Summary

### 1.1 Background

Phase 4.x delivered static analysis and security improvements. However, Python cold start is still bottlenecked by:

| Bottleneck | Current Cost |
|------------|--------------|
| .pyc file I/O | ~100-200ms per large module |
| Bytecode parsing | ~50-100ms |
| Memory allocation | ~30-50ms |

### 1.2 Goal

**30% faster cold start** through mmap-based PyCode caching:

```
Current:  Python → .pyc I/O → Parse → Execute
Fast:     Python → mmap cache → Zero-copy load → Execute
```

### 2.2 Fingerprint-Based Acceleration

| Existing Data | How It Accelerates |
|---------------|-------------------|
| `python_version` | Skip ABI check at runtime |
| `abi_tag` | Bundle path: `.velo/cache/{abi}/bundle.veloc` |
| `fingerprint` | Cache invalidation (rebuild only if changed) |
| `sys_path` | Skip path search, direct bundle lookup |
| `import_graph` | Order modules for sequential I/O |

### 2.3 Runtime Flow

```

│
├─ 1. Load fingerprint (from Phase 1.5 cache)
│     if fingerprint unchanged:
│         use cached bundle  ←── FAST PATH
│     else:
│         rebuild bundle

```

### 2.4 Bundle Format (.veloc)

Using **rkyv** for zero-copy index access:

```rust
use rkyv::{Archive, Deserialize, Serialize};

#[derive(Archive, Deserialize, Serialize)]
struct BundleHeader {
    magic: [u8; 4],           // "VELO"
    version: u32,             // Format version
    abi_tag: [u8; 32],        // "cp312-darwin-arm64"
    env_fingerprint: [u8; 32], // SHA-256 from Phase 1.5
    module_count: u32,        // Number of modules
    index_offset: u64,        // Offset to module index
}

#[derive(Archive, Deserialize, Serialize)]
struct ModuleEntry {
    name: String,             // "numpy.core"
    offset: u64,              // Data offset
    size: u64,                // Marshalled size
    source_hash: [u8; 32],    // For invalidation
}

#[derive(Archive, Deserialize, Serialize)]
struct BundleIndex {
    modules: HashMap<String, ModuleEntry>,  // O(1) lookup
}
```

**Why rkyv?**
- Zero-copy: directly access index from mmap'd buffer
- No deserialization: `archived.modules.get("numpy")` works instantly
- Faster than bincode for read-heavy workloads

### 2.5 Key Optimization: No Search

```
Traditional Python import:
for path in sys.path:        # 5-10 directories
    for ext in ['.py', '.pyc', '.so']:
        if exists(f"{path}/{module}{ext}"):
            return load(...)
# = (5-10) × 3 × stat() calls per import

Velo Bundle:
modules = bundle.index.get(module_name)  # O(1) hash lookup
return bundle.data[offset:offset+size]   # Direct slice
# = 0 syscalls per import (bundle already in memory)
```

### 2.6 Zero-Copy Optimization

#### Problem: Memory Copies

```
Traditional loading:
1. read() → kernel buffer     (copy 1)
2. kernel → user buffer       (copy 2)
3. slice → new bytes object   (copy 3)
4. marshal.loads()            (internal copies)
```

#### Solution: Minimize Copies

| Strategy | Copies | Implementation |
|----------|--------|----------------|
| Current (slice) | 3 | `data[i:j]` |
| **memoryview** | 1 | `memoryview(data)[i:j]` |
| **Rust mmap** | 1 | `Mmap::map() + &slice` |

#### Implementation: memoryview (Phase 5.0)

```python
class VeloLoader:
    def __init__(self, data: bytes):
        self.view = memoryview(data)  # No copy!
    
    def get_code(self, name):
        offset, size = self.index[name]
        # Only copy at final step (marshal requirement)
        return marshal.loads(bytes(self.view[offset:offset+size]))
```

#### Future: Rust mmap (Phase 5.1+)

```rust
// Zero-copy until Python boundary
let mmap = unsafe { Mmap::map(&file)? };
let module_data: &[u8] = &mmap[offset..offset+size];  // No copy!

// Single copy to Python heap
Python::with_gil(|py| {
    let bytes = PyBytes::new(py, module_data);
    marshal.call_method1("loads", (bytes,))?
});
```

#### Memory Flow Comparison

```
Traditional:
  File ──copy──▶ Buffer ──copy──▶ Slice ──copy──▶ marshal
                                   
Zero-Copy (memoryview):
  File ──copy──▶ Buffer ──view──▶ marshal
                   │
                   └── memoryview (no copy)

Zero-Copy (Rust mmap):
  File ──mmap──▶ Page Cache ──&[u8]──▶ Python
         │                      │
         └── kernel managed     └── single copy to Python heap
```
