Phase 4.x delivered static analysis and security improvements. However, Python cold start is still bottlenecked by:

| Bottleneck | Current Cost |
|------------|--------------|

**5x faster cold start** through bundled bytecode loading:

```
Current:  Python → sys.path search → .pyc I/O → Parse → Execute
Fast:     Python → bundle.veloc → memoryview → marshal.loads → Execute
```

### 2.5 Bundle Format (.veloc)

Using **rkyv** for zero-copy index access:

```rust
use rkyv::{Archive, Deserialize, Serialize};

#[derive(Archive, Deserialize, Serialize)]
struct BundleHeader {
    magic: [u8; 4],           // "VELO"
    version: u32,             // Format version
    abi_tag: [u8; 32],        // "cp312-darwin-arm64"
    env_fingerprint: [u8; 32], // SHA-256 from Phase 1.5
    module_count: u32,        // Number of modules
    index_offset: u64,        // Offset to module index
}

#[derive(Archive, Deserialize, Serialize)]
struct ModuleEntry {
    name: String,             // "numpy.core"
    offset: u64,              // Data offset
    size: u64,                // Marshalled size
    crc32: u32,               // Fast integrity check (~20 GB/s)
    source_hash: [u8; 32],    // Source file hash for cache invalidation
}

#[derive(Archive, Deserialize, Serialize)]
struct BundleIndex {
    modules: HashMap<String, ModuleEntry>,  // O(1) lookup
}
```

**Why rkyv?**
- Zero-copy: directly access index from mmap'd buffer
- No deserialization: `archived.modules.get("numpy")` works instantly
- Faster than bincode for read-heavy workloads

### 2.6 Import-Order Data Layout

Arrange module data by import dependency order for optimal cache hit:

```
Random order bundle:              Import-order bundle:
┌────────┬────────┬────────┐     ┌────────┬────────┬────────┐
│ torch  │ numpy  │ json   │     │ json   │ numpy  │ torch  │
└────────┴────────┴────────┘     └────────┴────────┴────────┘
     ↑        ↓        ↑           ────────────────────────▶
     └────────┴────────┘           Sequential read = prefetch
     Random access = cache miss    = cache hit
```

**Benefits**:
- OS prefetcher reads ahead sequentially
- Fewer page faults on mmap
- Better SSD/HDD throughput

**Implementation**:
```rust
// velo build: sort by import graph from Phase 4.0
fn build_bundle(project: &Path) -> Result<()> {
    let import_graph = load_import_graph(project)?;  // From velo analyze
    let sorted = topological_sort(&import_graph);
    
    for module in sorted {
        bundle.append_module(module);  // Write in dependency order
    }
}
```

### 2.7 Key Optimization: No Search

```
Traditional Python import:
for path in sys.path:        # 5-10 directories
    for ext in ['.py', '.pyc', '.so']:
        if exists(f"{path}/{module}{ext}"):
            return load(...)
# = (5-10) × 3 × stat() calls per import

Velo Bundle:
modules = bundle.index.get(module_name)  # O(1) hash lookup
return bundle.data[offset:offset+size]   # Direct slice
# = 0 syscalls per import (bundle already in memory)
```

### 2.8 Zero-Copy Optimization

#### Problem: Memory Copies

```
Traditional loading:
1. read() → kernel buffer     (copy 1)
2. kernel → user buffer       (copy 2)
3. slice → new bytes object   (copy 3)
4. marshal.loads()            (internal copies)
```

#### Solution: Minimize Copies

| Strategy | Copies | Implementation |
|----------|--------|----------------|
| Current (slice) | 3 | `data[i:j]` |
| **memoryview** | 1 | `memoryview(data)[i:j]` |
| **Rust mmap** | 1 | `Mmap::map() + &slice` |

#### Implementation: memoryview (Phase 5.0)

```python
class VeloLoader:
    def __init__(self, data: bytes):
        self.view = memoryview(data)  # No copy!
    
    def get_code(self, name):
        offset, size = self.index[name]
        # Only copy at final step (marshal requirement)
        return marshal.loads(bytes(self.view[offset:offset+size]))
```

#### Future: Rust mmap (Phase 5.1+)

```rust
// Zero-copy until Python boundary
let mmap = unsafe { Mmap::map(&file)? };
let module_data: &[u8] = &mmap[offset..offset+size];  // No copy!

// Single copy to Python heap
Python::with_gil(|py| {
    let bytes = PyBytes::new(py, module_data);
    marshal.call_method1("loads", (bytes,))?
});
```

#### Memory Flow Comparison

```
Traditional:
  File ──copy──▶ Buffer ──copy──▶ Slice ──copy──▶ marshal
                                   
Zero-Copy (memoryview):
  File ──copy──▶ Buffer ──view──▶ marshal
                   │
                   └── memoryview (no copy)

Zero-Copy (Rust mmap):
  File ──mmap──▶ Page Cache ──&[u8]──▶ Python
         │                      │
         └── kernel managed     └── single copy to Python heap
```

### 2.9 Native Extension Handling

`.so`/`.pyd` files cannot be marshalled. Strategy:

```
Module types:
├── Pure Python (.pyc)  → Bundle (marshal)
├── Native (.so/.pyd)   → Filesystem (fallback)
└── Package (__init__)  → Bundle + path reference
```

### 2.12 Design Principles

> [!IMPORTANT]
> Critical decisions that ensure long-term maintainability.

**1. Marshal-Only Serialization**
- Use standard `.pyc` / `marshal` format as bundle payload
- **Never** attempt to reconstruct `PyCodeObject` internal layout
- Reason: CPython internal structures have no stable ABI guarantee

**2. Import Semantics Preserved**
- Fast Loader does **not** change import execution semantics
- Module body code executes at normal import time
- No "pre-execution" or "lazy evaluation" changes

**3. Fallback-First Safety**
- Any parse/validation error → fallback to standard import
- Never panic on bundle corruption

### 2.15 Expert Architecture Recommendations

> [!TIP]
> Advanced optimizations for production robustness.

#### 2.15.1 Hybrid I/O Strategy

Dynamic selection based on bundle size:

```rust
const MMAP_THRESHOLD: usize = 16 * 1024 * 1024; // 16MB

fn load_bundle(path: &Path) -> Result<BundleData> {
    let size = path.metadata()?.len() as usize;
    if size < MMAP_THRESHOLD {
        // Small bundle: read() is faster (CPU cache friendly)
        Ok(BundleData::Memory(fs::read(path)?))
    } else {
        // Large bundle: mmap (lazy page loading, lower RSS)
        Ok(BundleData::Mmap(Mmap::map(&File::open(path)?)?))
    }
}
```

#### 2.15.2 Page-Aligned Data Layout

```rust
struct BundleLayout {
    header: Header,          // 64 bytes aligned
    index: Index,            // Variable size
    padding: [u8; N],        // Pad to 4096 bytes
    module_data: [u8],       // Page-aligned start
}
```

**Benefits**: True zero-copy with mmap, avoids false sharing.

#### 2.15.3 Native Extension Pre-loading

```python
# Early in Python startup (before import hook)
for so_path in bundle.native_deps:
    ctypes.CDLL(so_path, mode=ctypes.RTLD_GLOBAL)
```

**Benefits**: Centralized I/O, avoids repeated dlopen during import.

#### 2.15.4 Hierarchical Verification (Per-Module CRC32)

Two-tier integrity strategy:

| Level | Algorithm | Purpose | Speed |
|-------|-----------|---------|-------|
| **Bundle** | SHA-256 | Security/tamper detection | ~500 MB/s |
| **Module** | CRC32 | Fast corruption detection | ~20 GB/s |

```rust
struct ModuleEntry {
    name: String,
    offset: u64,
    size: u64,
    crc32: u32,  // Fast integrity check (40x faster than SHA-256)
}

fn verify_module(data: &[u8], entry: &ModuleEntry) -> bool {
    crc32_hash(&data[entry.offset..entry.offset + entry.size]) == entry.crc32
}
```

**Benefits**: Lazy verification, ~50μs per 10KB module vs ~2ms with SHA-256.

## 6. Risks & Mitigations

### 6.1 PyCodeObject Serialization (ABI Stability)

**Risk**: marshal format may change between Python versions.

**Mitigation**:
- Bundle path includes: `{python_version}/{abi_tag}/bundle.veloc`
- Use standard .pyc/marshal format (not custom bytecode)
- Never attempt to reconstruct PyCodeObject internals
- Always fallback on parse error

### 6.2 Zero-Copy vs Python Heap Boundary

**Risk**: `marshal.loads()` always copies to Python heap.

**Mitigation**:
- Accept single copy as minimum (memoryview reduces to 1 copy)
- For large modules: mmap reduces kernel→user transfer
- Future: explore Python 3.11+ internal APIs (PEP 659)

### 6.3 Native Extension Performance Trap

**Risk**: `.so/.pyd` fallback to filesystem breaks sequential I/O.

**Mitigation**:
- Pre-scan extensions at build time
- Large extensions (numpy, torch) → shared layers (Phase 5.2)
- Track fallback statistics for optimization

### 6.4 Cache Invalidation (Critical)

**Risk**: Stale bundle causes unpredictable runtime errors.

**Mitigation Hash Dimensions**:
```
cache_key = hash(
    source_path,          # Entry point
    import_graph_hash,    # Full dependency tree
    python_version,       # e.g., "3.12.0"
    abi_tag,              # e.g., "cp312-darwin-arm64"
    velo_version,         # Bundle format version
    [ext.content_hash for ext in c_extensions]  # Optional
)
```

### 6.5 Priority Summary

| Priority | Risk | Action |
|----------|------|--------|
| **P0** | Cache invalidation | Implement hash dimensions |
| **P0** | Version isolation | Bundle path includes abi_tag |
| **P1** | Native extension fallback | Pre-scan + layer strategy |
| **P2** | Incremental rebuild | Future optimization |
