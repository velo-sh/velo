## 1. Executive Summary

### 1.1 Background

Phase 3.0 delivered Zygote mode with 18-23% startup improvement:

| Project | CPython | Zygote Warm | Improvement |
|---------|---------|-------------|-------------|
| FastAPI | 572ms | 442ms | 23% faster |
| DataScience | 233ms | 187ms | 20% faster |
| Django | 401ms | 328ms | 18% faster |

However, users still need to manually invoke `velo run --zygote`. Phase 3.5 aims to make Zygote **seamless** for web frameworks.

### 1.2 Goal

Replace:
```bash
uvicorn main:app --reload
```

With:
```bash
velo serve main:app --reload
```

**Velo becomes the single command for Python web deployment.**

## 2. Proposed Features

### 2.1 `velo serve` Command

```bash
# Basic usage
velo serve main:app

# With uvicorn options
velo serve main:app --host 0.0.0.0 --port 8000 --reload

# With Zygote (default: enabled)
velo serve main:app --workers 4

# Disable Zygote
velo serve main:app --no-zygote
```

### 2.2 Zygote-Aware Worker Management

```
┌─────────────────────────────────────────────────────────────┐
│                    velo serve                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐     │
│  │   Master    │───▶│   Zygote    │───▶│   Workers   │     │
│  │   (Rust)    │    │  (Python)   │    │  (uvicorn)  │     │
│  └─────────────┘    └─────────────┘    └─────────────┘     │
│        │                  │                  │              │
│        ▼                  ▼                  ▼              │
│  - Parse CLI        - Pre-import       - Handle HTTP       │
│  - Manage workers     FastAPI/Django   - Serve requests    │
│  - Health checks    - Wait for fork    - Hot reload        │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 Auto-Detection

```rust
// Detect framework from app signature
match detect_framework(app_path) {
    Framework::FastAPI => preload(&["fastapi", "pydantic", "starlette"]),
    Framework::Django => preload(&["django"]),
    Framework::Flask => preload(&["flask"]),
    _ => preload_from_profile(),
}
```

## 3. Technical Design

### 3.1 CLI Interface

```rust
// src/cli.rs
#[derive(Parser)]
pub struct ServeArgs {
    /// ASGI application path (e.g., main:app)
    pub app: String,
    
    #[arg(long, default_value = "127.0.0.1")]
    pub host: String,
    
    #[arg(long, default_value = "8000")]
    pub port: u16,
    
    #[arg(long)]
    pub reload: bool,
    
    #[arg(long, default_value = "1")]
    pub workers: usize,
    
    #[arg(long)]
    pub no_zygote: bool,
}
```

### 3.2 uvicorn Integration Strategy

**Option A: Wrapper (Recommended for Phase 3.5)**
- Velo spawns uvicorn as subprocess
- Zygote pre-warms before uvicorn starts
- Simple, low risk

```bash
# Internally executes:
velo run --zygote -c "import uvicorn; uvicorn.run('main:app')"
```

**Option B: Native Server (Phase 4+)**
- Velo implements ASGI protocol directly
- Full control, more complex
- Deferred to later phases

### 3.3 Configuration

```toml
# velo.toml
[serve]
default_host = "127.0.0.1"
default_port = 8000
default_workers = 4

[serve.preload]
fastapi = ["fastapi", "pydantic", "starlette", "uvicorn"]
django = ["django"]
flask = ["flask", "werkzeug"]
```
