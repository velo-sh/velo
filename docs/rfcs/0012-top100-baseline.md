## Executive Summary

Velo aims to be the high-performance Python runtime for the AI era. To prove its robustness and performance advantages, we need a comprehensive baseline suite. This RFC proposes the **Top 100 Project Baseline**: a test suite that runs a "Hello World" (basic import and execution) for the top 100 most-downloaded Python packages from PyPI.

- **Goal**: Verify compatibility and Zygote speedup for 100 most popular packages.
- **Scope**: Automated environment setup, performance data collection, and baseline reporting.
- **Metric**: Comparison of CPython vs Velo (Zygote) startup times.

---

# Part I: Background & Motivation

## 1. Summary

Currently, Velo uses a few representative projects (FastAPI, Django, DataScience) for benchmarking. While useful, this doesn't cover the vast tail of the Python ecosystem. By testing the top 100 packages, we ensure that:
1. Velo's loading mechanism is compatible with diverse C-extensions and complex import chains.
2. Zygote pre-warming provides measurable benefits across different categories of libraries.
3. Regressions are caught early for the most critical packages in the ecosystem.

## 2. Motivation

### 2.1 The Problem
- Performance regressions might occur for specific libraries (e.g., those with complex metaclasses or unusual C-extensions).
- Users need confidence that Velo works with their specific stack.
- Internal testing is currently limited to a small sample size.

### 2.2 The Opportunity
- Create a "Gold Standard" of compatibility.
- Use the data for marketing and transparency.
- Provide a clear target for Phase 6.2+ optimizations.

# Part II: Proposed Changes

## 3. Tooling Infrastructure

### 3.1 `benchmark_top100.py` (Main Runner)
A new performance-oriented script that:
1. Uses a JSON list of the top 100 PyPI packages.
2. **Isolation & Cleanup**: Creates isolated `uv` environments for each package. To save disk space, environments are destroyed immediately after the test unless `--keep-envs` is specified.
3. **Execution Control**: Implements a strict **30-second timeout** per test to prevent infinite hangs during heavy package initialization (e.g., PyTorch).
4. **Verification**: Instead of relying solely on exit codes, it verifies that `stdout` contains a specific `IMPORT_SUCCESS` marker generated by the benchmark script.
5. **Results**: Persists results to `benchmarks/top100_baseline.json`.

### 3.2 `refresh_top100.py` (List Maintenance)
A maintenance script to fetch the latest top 100 packages from `hugovk/top-pypi-packages` and update the local JSON index.

## 4. Automation & Integration

- **Workflow**: `python3 scripts/run_top100_bench.py`.
- **CI Scheduling**: Due to high resource and time consumption, this is categorized as a **Tier 3 (Heavy)** test. It will run on a **weekly schedule** or when manually triggered, rather than on every PR.

# Part III: Implementation Details

## 5. Environment Isolation (SEC-P0-010)

Following the principles in `TEST_ARCHITECTURE.md`, each package MUST be installed in a fresh directory with its own `.venv`.

```
velo-benchmarks/
├── top100/
│   ├── <pkg_name>/
│   │   ├── pyproject.toml
│   │   ├── .venv/       <-- Destroyed after test
│   │   └── hello.py
```

## 6. Verification Logic

```python
# Generated hello.py
import <pkg>
print("IMPORT_SUCCESS")
```

The runner will capture output and verify:
1. `Exit Code == 0`
2. `"IMPORT_SUCCESS"` in `stdout`
3. Time taken < `TIMEOUT_SECS`

## 7. Reporting & Error Handling

Failed packages are logged to `benchmarks/top100_failures.log` with their full `stderr`. A partial run is considered successful if at least 90% of the packages pass.

# Part IV: Verification Plan

## 8. Acceptance Criteria

- [ ] All 100 packages can be installed and "imported" via Velo without error.
- [ ] Zygote mode shows >2x improvement for at least 80% of the top 100 packages.
- [ ] A `baseline.json` file is produced that can be used for regression comparison.
- [ ] Test suite completes within reasonable time limits (max 2 hours total).
