## 1. Summary

This RFC proposes enhancements to the Velo CLI, combining three complementary features:

1. **`velo serve`**: Zero-config ASGI/WSGI server wrapper (Uvicorn "exoskeleton")
2. **`velo analyze --graph`**: Static import graph visualization and statistics
3. **CLI Polish**: Improved user experience, error messages, and output formatting

These features work together to create "The Hook" - the entry point that makes users fall in love with Velo at first sight.

## 2. Motivation

### 2.1 The Problem

- Users currently need to type `uvicorn my_project.main:app --reload --host 0.0.0.0 --port 8000`
- The v0.6.0 Static Import Graph power is invisible to users
- Error messages are minimal and unhelpful
- Startup time improvements are not displayed

### 2.2 The Opportunity

- **`velo serve`**: One command to replace verbose uvicorn invocations
- **`velo analyze --graph`**: Show users exactly how much Velo optimizes their imports
- **Polish**: Make every interaction feel premium

## 4. Technical Specification

### 4.1 velo serve Enhancements

#### 4.1.1 Auto-Discovery (Zero-Config Mode)

When user runs `velo serve` without arguments:

```
1. Scan current directory for Python files
2. Look for app objects:
   - `app = FastAPI()`
   - `app = Flask(__name__)`
   - `application` in wsgi.py (Django)
3. Auto-detect entry point and start server
```

**AST Detection Pattern**:
```python
# Pattern: Assignment to 'app' with FastAPI/Flask call
app = FastAPI()  # -> main:app
app = Flask(__name__)  # -> main:app
```

#### 4.1.2 --dev / --prod Mode

```bash
velo serve --dev    # Default
  - Enable hot-reload
  - Verbose logging
  - Display startup timing
  - Show graph statistics

velo serve --prod
  - Disable hot-reload
  - Auto-set workers = CPU count
  - Enable static graph optimization
  - Verify uv.lock hash
```

#### 4.1.3 Turbo Hot-Reload

Two implementation options:

**Option A: Submodule-level reload (Complex)**
- Track file changes via `notify` crate
- Identify affected modules from Static Graph
- Reload only changed subgraph

**Option B: Fast process restart (Simple, Recommended for v0.6.1)**
- Track file changes via `notify` crate
- Terminate current process
- Restart with Velo's 10ms cold start
- User perceives instant reload

### 4.2 velo analyze --graph

New subcommand for `velo analyze`:

```bash
velo analyze --graph [project_dir]
```

**Output Format**:
```
Static Import Graph Analysis
============================
Modules:      127
Dependencies: 523 edges
Cycles (SCC): 2 detected
Load Order:   topologically sorted

Optimization Impact:
  stat() calls saved:  ~180 per startup
  Estimated speedup:   11.9x

Top 5 Most Connected:
  1. fastapi (42 dependents)
  2. pydantic (38 dependents)
  3. starlette.routing (25 dependents)
  ...
```

**JSON Export**:
```bash
velo analyze --graph --json > graph.json
```

### 4.3 CLI Polish

#### 4.3.1 Improved Error Messages

Before:
```
Error: missing app argument
```

After:
```
Error: No application specified

Velo couldn't find an ASGI/WSGI app in the current directory.

Try one of:
  velo serve main:app          # Explicit app path
  velo serve --help            # More options

Detected files:
  main.py (no 'app' object found)
  utils.py (no 'app' object found)
```

#### 4.3.2 Startup Timing Display

```
$ velo serve
✨ Detected FastAPI app in 'main.py'
📊 Static Graph: 127 modules, 523 edges
⚡ Startup: 12ms (saved ~180 stat() calls)
🟢 Listening on http://0.0.0.0:8000
```

## 8. Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| AST detection misses edge cases | Fallback to explicit `module:app` |
| Hot-reload breaks state | Document as expected behavior |
| Framework detection false positives | Priority order + explicit override |
