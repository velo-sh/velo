## 1. Summary

This RFC proposes enhancements to the Velo CLI, combining three complementary features:

1. **`velo serve`**: Zero-config ASGI/WSGI server wrapper (Uvicorn "exoskeleton")
2. **`velo analyze --graph`**: Static import graph visualization and savings report
3. **CLI Polish**: Improved user experience, error messages, and timing display

These features work together to create "The Hook" - the entry point that makes users fall in love with Velo at first sight.

## 2. Motivation

### 2.1 The Problem

- Users currently need to type `uvicorn my_project.main:app --reload --host 0.0.0.0 --port 8000`
- The v0.6.0 Static Import Graph power is invisible to users
- Error messages are minimal and unhelpful
- Startup time improvements are not displayed

### 2.2 The Opportunity

- **`velo serve`**: One command to replace verbose uvicorn invocations
- **`velo analyze --graph`**: Show users exactly how much Velo optimizes their imports
- **Polish**: Make every interaction feel premium

## 3. CTO-Approved Technical Adjustments

> [!IMPORTANT]
> The following adjustments were mandated during CTO review to reduce risk and maximize delivery quality.

### 3.1 Instant Restart (Not Hot Module Replacement)

**Risk**: True Python HMR (in-memory hot module replacement) is extremely difficult and unstable (stale object references, state consistency issues).

**Velo's Advantage**: Ultra-fast startup (10ms).

**Decision**:
- ❌ DO NOT attempt complex in-memory hot replacement
- ✅ DO implement "Instant Restart" (kill process → restart in 20ms)
- **Rationale**: With 10ms startup, "kill + restart" is perceived as instant but is engineering-clean

### 3.2 Signal Handling for Uvicorn Proxy

**Risk**: When running `uvicorn.run()` via pyo3, Ctrl+C signal handling can conflict between Rust and Python.

**Implementation Requirements**:
- Rust MUST own the Ctrl+C signal handler
- On exit signal, Rust gracefully shuts down Python's event loop
- In dev mode, direct exit is acceptable

### 3.3 Enhanced "Savings Report" Output

**Requirement**: The `velo analyze` output must be a "bill" format for maximum user impact:

```
Startup Savings Report
======================
Modules analyzed:     540
Traditional Python:   2,160 stat() syscalls
Velo optimized:       0 stat() syscalls
Estimated time saved: ~180ms
```

## 4. Technical Specification

### 4.1 velo serve Core

#### 4.1.1 Uvicorn Transparent Proxy

```rust
// Rust-side responsibilities:
// 1. CLI argument parsing (existing)
// 2. pyo3 bridge to call uvicorn.run()
// 3. Signal handling (Ctrl+C ownership)
// 4. Process lifecycle management
```

**Critical**: Avoid zombie processes on Ctrl+C.

#### 4.1.2 Auto-Discovery (Zero-Config Mode)

When user runs `velo serve` without arguments:

```
1. Scan current directory for Python files
2. AST scan or regex match for app objects:
   - `app = FastAPI()`  → main:app
   - `app = Flask(__name__)` → main:app
   - `wsgi.py` exists → Django mode
3. Friendly error if not found: "Did you mean...?"
```

**MVP Approach**: Use RustPython-parser or simple regex matching for v0.6.1.

#### 4.1.3 --dev / --prod Mode

```bash
velo serve --dev    # Default
  - Enable Instant Restart (file watching)
  - Verbose logging
  - Display startup timing breakdown

velo serve --prod
  - Disable file watching
  - Auto-set workers = CPU count
  - Verify uv.lock hash
```

### 4.2 Instant Restart (File Watching)

**Implementation**:
1. Integrate `notify` crate for file system events
2. On file change: Kill child process → Spawn new child
3. **Velo Advantage**: Only watch files in the dependency graph (ignore node_modules, etc.)

```
File change detected: src/models.py
↓
[Velo] Restarting... (child PID: 12345 → killed)
[Velo] Started in 12ms (new PID: 12346)
```

### 4.3 velo analyze --graph

**Savings Report Format**:
```
$ velo analyze --graph

Static Import Graph Analysis
============================
Project:              ./myapp
Modules in graph:     127
Dependency edges:     523
Cycles (SCC):         2 detected

Startup Savings Report
----------------------
Traditional Python:   ~540 stat() syscalls
Velo (Static Graph):  0 stat() syscalls
Estimated savings:    ~180ms per cold start

Top 5 Most Connected Modules:
  1. fastapi           (42 dependents)
  2. pydantic          (38 dependents)
  3. starlette.routing (25 dependents)
  4. httpx             (18 dependents)
  5. sqlalchemy.orm    (15 dependents)
```

**JSON Export**:
```bash
velo analyze --graph --json > graph.json
```

### 4.4 CLI Polish

#### 4.4.1 Colored Output

Use `colored` crate. Velo logs should be visually distinct from app logs:
- Velo prefix: Cyan color
- Errors: Red
- Success: Green

#### 4.4.2 Startup Timing Breakdown

```
$ velo serve
✨ Detected FastAPI app in 'main.py'
⏱  Timing: Load 2ms | Graph 1ms | Init 5ms | Total 8ms
📊 Graph: 127 modules, 523 edges (0 stat() calls)
🟢 Listening on http://0.0.0.0:8000
```

## 8. Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| AST detection misses edge cases | Fallback to explicit `module:app` |
| Signal handling conflicts | Rust owns Ctrl+C, clean Python shutdown |
| Zombie processes | Explicit process kill before exit |
| Instant restart loses state | Document as expected behavior (stateless) |
