## 1. Executive Summary

### 1.1 Background

Phase 4.0 delivered `velo analyze` for automatic import bottleneck detection. However, two issues remain:

1. **Legacy Hardcoding**: `src/serve/framework.rs` still contains hardcoded framework detection
2. **Security Risk**: `velo analyze` executes user code without warning

### 1.2 Goal

Clean up legacy patterns and add safety mechanisms:

```bash
# Deprecated warning when using hardcoded detection
warning: Framework enum is deprecated since v0.4.1

# Safe analysis without code execution
velo analyze --dry-run

# Skip confirmation for CI/scripts
velo analyze --yes
```

---

## 2. Technical Design

### 2.1 Deprecation Strategy

```rust
// src/serve/framework.rs
#[deprecated(since = "0.4.1", note = "Use runtime analysis via velo analyze")]
pub enum Framework {
    FastAPI,
    Django,
    Flask,
    Starlette,
    Unknown,
}
```

### 2.2 New CLI Flags

```rust
// src/cmd/analyze.rs
#[derive(Parser)]
pub struct AnalyzeArgs {
    // ... existing fields ...
    
    /// Static analysis without executing code
    #[arg(long)]
    pub dry_run: bool,
    
    /// Skip confirmation prompt
    #[arg(long, short = 'y')]
    pub yes: bool,
}
```

### 2.3 Consent Prompt

```rust
if !args.dry_run && !args.yes && is_interactive() {
    eprintln!("⚠️  WARNING: This will execute your Python code.");
    eprintln!("   Use --dry-run for static analysis.");
    eprint!("Continue? [y/N]: ");
    
    if !read_confirmation() {
        return Ok(());
    }
}
```
