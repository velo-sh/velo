## 2. 大一统 Merkle 范式：IPFS + Git + RAM

通用意图网格 (UIG) 将整个软件执行层视为一个**全球 Merkle DAG（有向无环图）**。这把分发、执行和安全统一为一个单一的数学原语。

### 2.1 镜像即 Merkle Tree
在 Velo 中，镜像不再是扁平的文件，而是一棵 **Merkle 树**：
- **根哈希 ($H_{root}$)**：整个计算环境的唯一标识符（“区块头”）。
- **分支哈希 ($H_{branch}$)**：模块化的逻辑层（如 Ubuntu 底座、Python 运行时、应用逻辑）。
- **叶子哈希 ($H_{leaf}$/Pages)**：原子级的 4KB 或 64B 逻辑块。

### 2.2 执行即懒加载 (Lazy Traversal)
这实现了无论镜像多大都能在 **1ms 内启动**。Velo 将执行形式化为 **Merkle DAG 的遍历**：

$$Execution = Traverse(Merkle_{DAG}, PC_{logic})$$

其中：
- **$PC_{logic}$**: (逻辑哈希 $H_{logic}$, 偏移量 $O_{logic}$)。
- **内存读取**: $Resolve(H_{logic} \to H_{leaf} \to 物理页)$。

### 2.3 传输即树同步 (Set Reconciliation)
“下载”镜像现在只是 **树差异同步 (Tree Delta Sync)**：
- 我们不搬运字节；我们协调哈希。如果节点已经有 Ubuntu 分支，它只获取唯一的应用分支增量。

### 2.4 数学级信任链 (Chain of Trust)
安全由 Merkle 结构原生强制执行。CPU 执行的每一位代码都必须有一个哈希，能够**回溯验证**到签名的 $H_{root}$。任何不在树上的块对硬件来说都是不可执行的。

## 3. 软件即不可变意图

**公理**：内存中的软件不是地址的集合；它是一个签名的、不可变的**内容**与**意图**块。

- **以地址为中心 (传统)**：内存是位置上的一桶字节。安全是对桶的锁定（页表）。
- **以内容为中心 (Velo)**：逻辑是密码学身份。安全是**意图的完整性**。

## 4. 务实的革命路径：Velo Fleet v2.0

基于专家委员会的审议，Velo Fleet 从“硬件优先”转向“**软件错觉优先**”的执行策略。

### 4.1 指针稳定性：JIT-Rebasing
不再仅仅依赖昂贵的硬件级 RIP，我们在 `fork()` 的瞬间进行闪电般的指针重定位，实现零运行时开销。

### 4.2 混合 L-MMU (Hybrid Granularity)
对于不可变锚点使用大页（1GB/2MB），仅对可变 Delta 使用细粒度（64B）追踪，平衡密度与硬件复杂度。

### 4.3 “特洛伊木马”战略 (GTM)
用户上传标准 Docker 镜像，Velo 后台自动将其拆解为逻辑哈希（全球逻辑注册表），实现透明的原生加速。
